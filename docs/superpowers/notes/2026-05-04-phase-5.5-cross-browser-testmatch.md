# Phase 5.5 — Cross-browser testMatch expansion findings

**Date:** 2026-05-04  
**Branch:** feat/vision-audit-remediation  
**Task:** Expand `mobile-webkit` and `desktop-firefox-touch` testMatch to include canonical DOM specs.

## Motivation

Phase 2.2 found that `mobile-webkit` and `desktop-firefox-touch` only ran `mobile-smoke.spec.ts` and `mobile-tap.spec.ts`. Canonical DOM flows (theme, panel, launcher) were never exercised on WebKit or Firefox, meaning CSS/DOM regressions in those paths would go undetected.

## Conservative initial candidate set

Three specs chosen as most likely to be cross-browser-portable (no clipboard, no GPU/map):

| Spec | Rationale |
|---|---|
| `theme-and-responsive.spec.ts` | Pure CSS/DOM: `document.documentElement.classList`, `emulateMedia`. No platform APIs. |
| `panel-and-deeplink.spec.ts` | DOM-driven via URL hash. Mobile-aware "Bottom sheet" tests already exist. |
| `launcher-card-loading-states.spec.ts` | Route-stub-driven (`page.route`), fully deterministic. No real network. |

## Per-spec, per-project pass/fail matrix

| Spec | `mobile-webkit` | `desktop-firefox-touch` |
|---|---|---|
| `theme-and-responsive.spec.ts` (3 tests) | 3/3 PASS | 3/3 PASS |
| `launcher-card-loading-states.spec.ts` (4 tests) | 4/4 PASS | 4/4 PASS |

### panel-and-deeplink.spec.ts failures (both projects)

**Test 1:** `Country Panel > border chip navigates to neighbor country`  
**Test 2:** `Country Panel > panel shows government type from CIA Factbook`

**Root cause:** project-config viewport mismatch, not a browser engine bug.

- `mobile-webkit` uses `devices['iPhone 14']` → 390×664px viewport.
- `desktop-firefox-touch` uses 412×839px viewport.
- Both are below the app's `1024px` desktop breakpoint (`useMediaQuery('(min-width: 1024px)')`).
- On mobile, `showSecondary = isDesktop || expanded` defaults to `false`.
- Secondary fields (Government/CIA Factbook, border chips) are hidden until the user taps the expand button.
- The failing tests don't call expand; they assume desktop-mode rendering.

**Classification:** project-config (not a browser engine bug, not a real regression).

The `Country Panel` describe block in `panel-and-deeplink.spec.ts` is authored for a desktop viewport. The `Bottom sheet on mobile` describe block passes fine on both projects.

## Triage decisions

| Spec | Decision | Reason |
|---|---|---|
| `theme-and-responsive.spec.ts` | **KEEP** in both projects | 3/3 pass; genuinely exercises theme toggle and `prefers-color-scheme` on WebKit/Firefox. |
| `launcher-card-loading-states.spec.ts` | **KEEP** in both projects | 4/4 pass; route-stub tests are browser-agnostic and confirm the launcher error states render correctly on both engines. |
| `panel-and-deeplink.spec.ts` | **EXCLUDED** from both projects | 2/7 tests fail due to mobile-viewport project config (not browser engine). The failing tests need a ≥1024px viewport to pass; these projects don't provide one. The mobile-specific bottom-sheet tests are already covered in `chromium` (which runs a desktop viewport by default). |

## Backlog items

None. No real cross-browser bugs were found. The `panel-and-deeplink.spec.ts` failures are a known test-design limitation (desktop-assumption tests in the `Country Panel` describe block), not a production defect.

A future improvement would be to split `panel-and-deeplink.spec.ts` into a `panel-desktop.spec.ts` and `panel-mobile.spec.ts`, allowing the mobile tests to be added to all four non-GPU projects. Filed as a low-priority backlog item under Phase 5.4.
