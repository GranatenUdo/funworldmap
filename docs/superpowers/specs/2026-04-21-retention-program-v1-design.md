# Retention Program v1 — Daily Puzzle, Streak, Share

**Date:** 2026-04-21
**Status:** Draft — pending user review
**Depends on:** [`2026-04-20-launcher-landing-state-design.md`](2026-04-20-launcher-landing-state-design.md) (shipped as PR #7). Retention v1 extends the launcher as its host surface.
**Supersedes:** the launcher spec's "Landing-state copy variants, A/B test machinery" deferral (that paragraph is replaced by this spec's launcher-evolution section).

---

## Overview

Turn funworldmap's existing two single-player game modes into a daily-habit product without violating the no-backend principle or eroding the educational positioning. Users get one shared puzzle per mode per day, played with three attempts (best-of-3 scoring). A cross-session streak, an inline calendar of past days, and a text share artifact give the Wordle-style virality + return loop. The launcher landed in PR #7 hosts every retention surface; no new modals, no new routes beyond `#daily/…`.

**Primary goal:** day-1 and day-7 retention uplift against a 14-day pre-launch baseline. Secondary: virality (deep-link return traffic), session depth, shareability.

**Explicitly not a goal:** acquisition through paid channels, leaderboards, push notifications, or any pattern that would require operating a runtime backend.

## Scope

### In v1

1. **Daily puzzle per mode.** One country + one city chosen per calendar day (local). Same pair visible to all players worldwide (modulo timezone — see Known Limitations).
2. **Three attempts per daily, best-of-3 scoring.** Each attempt is scored 0–100 via the existing distance-decay formula. The day's recorded score is the max across three attempts.
3. **Cross-session streak.** Consecutive local-date days on which the user completed ≥ 1 daily (either mode counts). Resets on a missed day.
4. **Streak-milestone celebrations.** Brief in-launcher overlay on reaching 3, 7, 14, 30, 100-day streak.
5. **Launcher evolution.** Mode cards show today's daily state (unplayed / played / unavailable); secondary "Play free mode" link preserves the existing endless flow.
6. **Inline calendar history.** 5×7 grid of the past 5 weeks, cells show per-mode completion, click navigates to that day's reveal.
7. **Share flow.** Post-daily overlay with plain-text share string (5-emoji precision bar per attempt strip per mode + score + streak + URL). Uses `navigator.share` with clipboard fallback.
8. **Deep-link URLs.** `/#daily/YYYY-MM-DD[/<modeId>][/reveal]` routes.
9. **Daily content pipeline.** `public/daily/index.json` rolling file, generated by a GitHub Action running 4× daily. Curated country + city pools in `scripts/daily-content/`.
10. **Cloudflare Web Analytics.** Privacy-preserving, free, no PII. Requires fronting GH Pages with Cloudflare (one-time DNS setup).
11. **Custom event tracking.** Via a thin `src/lib/analytics.ts` wrapper. Events enumerated in §11.

### Out of v1 (deferred to `docs/roadmap.md`)

- Push notifications (would require a push service).
- Yesterday's-global-average score overlay (requires analytics aggregation pipeline — v1.1 candidate).
- Canvas-rendered PNG share image.
- Retroactive free-play of past dailies (calendar cells are reveal-only in v1).
- Regional/difficulty packs, alternative pools.
- Per-timezone daily rollover (v1 ships a bounded 6 h timezone lag — see Known Limitations).
- Streak-freeze / streak-save mechanics.
- i18n of share text or daily copy (English-only v1).
- Achievements, badges, meta-progress "world explored" map coloring.
- Multiplayer, leaderboards.

## User flows

### Returning user, day 3 of streak

1. Opens fresh tab at `/` → launcher appears, `🔥 2-day streak` pill above cards.
2. Country-Pinning card shows `TODAY · COUNTRY — not played — [Play]`.
3. Clicks Play → plays three attempts at today's country → scores 87 → reveal shows target + three guesses → game-over overlay includes share block + "Play today's city →" CTA.
4. Clicks the CTA → plays city daily → scores 81 → game-over overlay shows combined share.
5. Shares. Dismisses overlay. Launcher reappears with both cards `✓ played`, streak pill now `🔥 3-day streak`. Streak-milestone overlay fires (3-day milestone) — dismissible, 2-second auto-dismiss.
6. Clicks "Just explore the map" to exit to regular exploration.

### First-time share-recipient

1. Friend sends `funworldmap.com/#daily/2026-04-21/country-pinning`.
2. User lands directly on today's country daily — launcher is bypassed per the deep-link rule.
3. Plays 3 attempts → game-over overlay. Share block shows streak "Day 1" framing.
4. Clicks "Play today's city →".
5. After city daily → share + "Come back tomorrow to keep your streak going" copy.
6. Closes overlay → launcher re-appears with day-1 streak and both cards played.

### User on a broken streak

1. Missed 2 days. Opens fresh tab.
2. Launcher shows `Start your streak — play today's daily.` Streak pill hidden (current = 0).
3. Calendar panel (accessed via `Past 30 days →` link) shows the 2 missing days as greyed cells without dots.
4. Plays today's country → streak becomes 1. Launcher refreshes copy to `🔥 1-day streak`.

## Data model

### Server: rolling daily index

Single file `public/daily/index.json`, regenerated by the GitHub Action. Past-and-today only — no future dates emitted (protects against view-source spoilers). Schema:

```json
{
  "generatedAt": "2026-04-21T00:15:00Z",
  "window": {
    "start": "2026-03-22",
    "end":   "2026-04-21"
  },
  "days": {
    "2026-04-21": {
      "country": { "cca3": "PER" },
      "city":    { "id":   "per-lima" }
    },
    "2026-04-20": { "country": { "cca3": "NOR" }, "city": { "id": "nor-oslo" } },
    "2026-04-19": { ... }
  }
}
```

- **References only.** Country by `cca3`, city by `id`. No duplicated names / coords / flags — the client joins against the existing `countries.json` and `cities.json`.
- **Window.** 30-day retention: `window.start = today - 30 days`; `window.end = today`.
- **Idempotent regeneration.** The Action reads the existing `index.json`, preserves all past entries verbatim, drops entries older than 30 days, appends today's entry if missing. Never mutates historical entries.
- **Size.** ~60 bytes × 31 days ≈ 2 KB gzipped. Fetched once per session; subsequent navigations served from HTTP cache (CF edge TTL + browser cache). No service worker — the project does not ship a PWA.

### Client: local history

Single `localStorage` key `funworldmap-daily-history`. Schema:

```json
{
  "version": 1,
  "streak": {
    "current": 7,
    "longest": 12,
    "lastActiveDate": "2026-04-21",
    "lastMilestoneShown": 7
  },
  "days": {
    "2026-04-21": {
      "country-pinning": {
        "score": 87,
        "attempts": [
          { "guessCca3": "BOL", "score": 42 },
          { "guessCca3": "ECU", "score": 68 },
          { "guessCca3": "PER", "score": 100 }
        ],
        "completedAt": 1745280123456
      },
      "city-guessing": null
    }
  }
}
```

- **`attempts`** stored per day for reveal replay + share-strip rendering.
- **`score`** is the max across attempts (best-of-3).
- **`lastMilestoneShown`** records the highest milestone *threshold* the user has already seen (value in `{0, 3, 7, 14, 30, 100}`). Prevents the same milestone from firing twice across multi-tab play or streak-regression scenarios.
- **`version`** gates future migrations. Unknown versions → reset to empty, no data loss beyond current day (acceptable, migrations added before first bump).
- **Retention window.** Client prunes `days` entries older than 90 days on read. 90 > 30-day server window, so calendar always has all it needs.
- **Storage cost.** ~250 B × 60 entries × 2 modes ≈ 30 KB after years. Well within budget.

### Timezone policy

**Puzzle date and streak date both use the user's local date.** Wordle and equivalents use this policy; it avoids the "my streak broke while I slept" footgun. Tradeoff: timezones ahead of UTC experience a bounded daily-syncing window — see Known Limitations.

**Implementation:** a pure `toLocalDateString(d: Date): string` helper in `src/game/daily/dates.ts` that manually assembles `YYYY-MM-DD` from `d.getFullYear()`, `d.getMonth() + 1`, `d.getDate()` (all zero-padded). Deliberately avoids `toLocaleDateString`, which returns locale-varying formats (Finnish locale: `"21.4.2026"`; Japanese: `"2026/4/21"`). Unit-tested against fixture dates in multiple locales.

## Daily content pipeline

### Curated pools

Two files under `scripts/daily-content/`:
- `country-pool.json` — array of CCA3 strings. Target: ~100 countries.
- `city-pool.json` — array of city ids matching `cities.json`. Target: ~200 cities (capitals + major non-capitals, weighted toward recognition).

**Curation criteria (in order of priority):**
1. **Political neutrality.** Exclude entries where the daily puzzle would implicitly take a side on contested sovereignty, borders, or naming: Taiwan, Kosovo, Palestine, Western Sahara, Jerusalem, Crimea, Taipei (as capital) — any choice on these is editorial. Free mode stays on the full pool; daily uses the filtered one.
2. **Unambiguous recognition.** Exclude microstates and non-sovereign territories whose names/locations typical users cannot place (Vatican aside — it's recognizable enough). Retain teaching-value clarity over edge-case trivia.
3. **Global balance.** No continent dominates. Roughly: Europe 25 %, Asia 25 %, Africa 20 %, Americas 20 %, Oceania 10 %. Prevents regional bias in the daily series.
4. **Stable names/IDs.** Exclude entries with recent naming disputes (e.g., Türkiye vs. Turkey) where `countries.json` may churn.

**Curation ownership:** Tobias (repo owner) approves the final list before Phase 2 merge. The pool is a design artifact, not generated code.

Curation happens alongside Phase 1 implementation; blocks Phase 2 merge.

### Deterministic picker

```
seed(date, salt) = sha256(date + salt).mod(pool.length)
```

Rejection-sampling: if the chosen entry appeared in the last 30 days, increment `salt` and re-roll. Guarantees no repeats within the window.

Determinism means regenerating the index is a no-op for past days — safe to re-run.

### GitHub Action

`.github/workflows/daily-puzzle.yml`:
- Cron: runs **4 times daily** at `00:15`, `06:15`, `12:15`, `18:15` UTC.
- Checks if today's local-date entry (in UTC terms) is present; appends if missing.
- Prunes entries older than 30 days.
- Commits on change with message `chore(daily): update daily-puzzle window`.
- Commit triggers the existing `deploy.yml` workflow → new `index.json` deployed within ~2 min.

Rationale for 4×/day cadence: one cron/day means timezones ahead of UTC see stale data for up to 14 h on a day-rollover. 4×/day caps that lag at ~6 h — acceptable for v1, listed as a Known Limitation.

### CI validation

New script `scripts/daily-content/validate-pools.ts` runs in CI:
- Fails if any id in `country-pool.json` is not present in `src/data/countries.json`.
- Fails if any id in `city-pool.json` is not present in `src/data/cities.json`.
- Runs on every PR that touches data files or the pools.

Prevents silent corruption when a data update removes an id.

## Game mechanic changes

### Three attempts per daily, best-of-3

The existing game framework (`src/game/shared/GameSessionProvider.tsx`) handles N-round sessions with one target per round. Daily is **one target with three attempts** — a new shape.

Two small extensions:

1. **`GameSession` gains `attemptsPerRound: number`** (default 1 for existing modes). Daily sessions pass `3`.
2. **`submitGuessInput` behavior change when `attemptsPerRound > 1`:** does not auto-advance rounds until all attempts exhausted or user chooses to reveal. Records each attempt to `session.currentAttempts[]`.

Mode handlers (`country-pinning/scoring.ts`, `city-guessing/scoring.ts`) are unchanged — they score single guesses as today. The session aggregates.

### Between-attempt feedback

After a wrong attempt:
- **Country-pinning:** the guessed country is highlighted on the map with a distance label (e.g., "1,200 km off"). No directional hints beyond distance.
- **City-guessing:** the guess point is shown with a distance label. No direction arrow to the target.

After third attempt (or after user clicks "Reveal"): full reveal showing target + all attempts + distances + final best-of-3 score.

Design tension: distance feedback after attempt 1 substantially narrows the search space for attempt 2. This is intentional — the game becomes about narrowing in, not cold-guessing. Share strip captures the journey (see §Share).

### Scoring

- Per attempt: existing `scoreGuess`/`scoreCityGuess` (0–100 each).
- Per daily (per mode): `max(attempt1, attempt2, attempt3)`. Stored in `days[date][modeId].score`.
- Share text uses the best-of-3 score.
- No penalty for using all three attempts — strategic recovery is rewarded, not punished.

## Launcher evolution

### Anatomy (revised from launcher-landing-state spec)

Top to bottom:
1. **Wordmark.**
2. **Streak pill + history link row.**
   - `🔥 7-day streak · Past 30 days →` when `current ≥ 1`.
   - `Start your streak — play today's daily · Past 30 days →` when `current === 0`.
3. **Two mode cards** (see states below).
4. **"Just explore the map"** dismiss link (unchanged).

### Mode card states

Each card is one of three states, exposed via `data-testid="launcher-card-{modeId}-state"`:

**`unplayed`** — card header `TODAY · COUNTRY` / `TODAY · CITY`. Copy `Pin today's country` / `Find today's city`. Primary button `Play · 3 attempts`. Secondary link `Play free mode →`. Compact footer `BEST 920/1000` (free-mode best).

**`played`** — card header same. Completed state shows `✓ Peru · 87/100` (best-of-3). Subtle green left-border tint. Primary button `See reveal · Share`. Secondary link `Play free mode →`. Compact footer same.

**`unavailable`** — triggered when `index.json` fetch fails, today's date is outside `window`, or service worker has no cache. Primary copy `Today's daily is syncing.` Primary button swaps to `Play free mode`. Footer hidden.

### Visibility state machine update

`useLauncherVisibility` currently computes `visible = isBareRoot(hash) && !dismissed && idle`. Extended:

```ts
isBareRoot(hash)   = hash === ''  || hash === '#'
isDailyRoot(hash)  = matches /^#?daily\/\d{4}-\d{2}-\d{2}$/  // no mode, no reveal
visible            = (isBareRoot(hash) || isDailyRoot(hash)) && !dismissed && session.status === 'idle'
```

When `isDailyRoot` matches, the launcher opens anchored to that date — mode cards show that date's puzzles. This is the shared-URL target.

Other hash shapes (`/#daily/<date>/<modeId>`, `/#daily/<date>/reveal`, `/#daily/<date>/<modeId>/reveal`) bypass the launcher as today's `/#game/…` URLs do.

### Streak-milestone celebration

When a user's completion pushes streak across a milestone threshold (3, 7, 14, 30, 100), a small celebration overlay renders above the launcher cards:
- Copy varies: `3 days — off to a strong start`, `7 days — a full week`, `14 days — two weeks`, `30 days — a full month`, `100 days — a hundred days`.
- Auto-dismiss after 2.5 s; dismissible via click or Escape (Escape then continues to dismiss launcher as normal).
- `lastMilestoneShown` in localStorage prevents double-firing in multi-tab.
- `prefers-reduced-motion` collapses animation to near-instant fade.

### Animations (additions only)

Existing keyframes unchanged. Three new:
- `launcher-streak-in` — 180 ms fade-up, starts at t=30 ms (before wordmark).
- `launcher-history-in` — 220 ms slide-down for the history panel.
- `launcher-milestone-in` — 260 ms scale-up celebration overlay.

## Streak & calendar

### Rules (precise)

Let `today = local date`, `last = streak.lastActiveDate`.

On a daily completion:
1. If `last === today`: no-op on `current` (same-day other-mode doesn't double).
2. Else if `last === today - 1 day`: `current += 1`.
3. Else: `current = 1`.

Then:
- `longest = max(longest, current)`.
- `lastActiveDate = today`.
- If `current` crosses a milestone threshold and `lastMilestoneShown < current`: trigger celebration, set `lastMilestoneShown = current`.

No automatic reset on missed days — `current` is derived on completion, not on page load. A user who plays after a 5-day gap sees `current = 1`, not `0`.

Launcher displays `current` via the streak pill; if `current === 0` AND `days` has any entries AND `last` is before `today - 1`, the pill shows the broken-streak invitation copy.

### Calendar panel

Inline-expanding panel beneath the mode cards. Toggle via `Past 30 days →` link. Structure:

- **7-column ISO-week grid, 5 rows = 35 cells.** Last 5 weeks ending on current week.
- **Cells before `window.start`** render as greyed `—` placeholders (not interactive).
- **Cells within window:**
  - Un-played: date only, neutral background, interactive (→ reveal URL).
  - Played one mode: one dot (teal for country-pinning, coral for city-guessing).
  - Played both modes: two dots.
  - Today: teal ring border.
- **Streak connector:** subtle horizontal line between consecutive played cells, breaks on misses.
- **Captions below grid:** `Current: 7 · Longest: 12 · Days played: 21`.

Interaction:
- Click played cell → `/#daily/<date>/reveal`.
- Click un-played in-window cell → `/#daily/<date>/reveal` (shows answer without score).
- Click rolled-off cell → non-interactive; hover tooltip `No longer available`.

Accessibility:
- `role="grid"`, `role="row"`, `role="gridcell"`.
- Arrow-key navigation between cells; Enter activates.
- Each cell's `aria-label`: `"April 15 2026, country-pinning 87, city-guessing 81, today"` with fields present only as applicable.
- Focus trap extends into the panel when open.
- Nested Escape: first press closes panel, second press dismisses launcher.

## Share flow + deep-link URLs

### Share text (plain, no-spoiler, scale-consistent)

```
funworldmap · 04-21
🌍 Country  🟥🟧🟩  87/100
🏙️ City     🟥🟨🟩  81/100
🔥 7-day streak
funworldmap.com/#daily/2026-04-21
```

- **3-square attempt strip per mode** — one square per attempt, color encodes that attempt's score quintile: 🟩 (90–100) · 🟨 (70–89) · 🟧 (50–69) · 🟥 (30–49) · ⬛ (0–29).
- **Score after strip** — best-of-3, always `/100` (identical scale for both modes).
- **Un-played mode line**: `🏙️ City  ⬜⬜⬜  not played`.
- **Streak line omitted** when `current === 0`.
- **Country/city names deliberately omitted** — preserves puzzle for share recipients who haven't played.

### Share dispatch

`<DailyShareBlock>` mounts inside `GameOverOverlay.tsx` only when `session.kind === 'daily'`. Primary button `Share`:
- If `navigator.share` available (most mobile, Safari): `navigator.share({ title, text, url })`.
- Otherwise: `navigator.clipboard.writeText(text + '\n' + url)` + toast `Copied!`.
- Secondary link `Copy link only` → clipboard with URL only.

### Deep-link URL shapes

New `daily` variant in `src/lib/hashState.ts`:

```ts
| { kind: 'daily'; date: string; modeId: ModeId | null; reveal: boolean }
```

| URL | Behavior |
|---|---|
| `/#daily/YYYY-MM-DD` | Launcher anchored to that date. Mode cards show that day's puzzles. |
| `/#daily/YYYY-MM-DD/<modeId>` | Bypasses launcher. Today + un-played → start daily. Past or already played → route to `.../reveal`. |
| `/#daily/YYYY-MM-DD/reveal` | Read-only reveal of both modes for that date. No play. |
| `/#daily/YYYY-MM-DD/<modeId>/reveal` | Single-mode reveal. |

Edge cases:
- Future date → one-shot toast `That date hasn't arrived yet.` + redirect to `/`.
- Date outside 30-day window → toast `That daily has rolled off.` + redirect to `/`.
- Invalid date format → silent redirect to `/`.

### Default shared URL

Share button always uses `/#daily/<date>` (no mode) — recipients see both today's puzzles. Calendar-cell clicks use `/#daily/<date>/reveal` for read-only context.

## Analytics — Cloudflare Web Analytics

### Infrastructure

- **Cost: $0/month.** Cloudflare Web Analytics is free, unlimited sites, no cookies, no PII.
- **Setup (one-time):** point domain nameservers at Cloudflare; enable Proxied DNS in front of `funworldmap.github.io`; enable Web Analytics on the CF dashboard; paste the one-line script tag into `index.html`.
- **No code dependency.** CF Web Analytics collects page-view + core vitals passively.

### Custom events

Custom events are tracked via a thin wrapper module `src/lib/analytics.ts`:

```ts
export function track(name: EventName, props?: Record<string, string | number>): void
```

Internals:
- Calls `window.__cfBeacon?.trackEvent(name, props)` if the CF script has loaded.
- No-op if `navigator.doNotTrack === '1'`.
- No-op in e2e (detects `window.__PLAYWRIGHT__` set by `beforeEach`).
- In e2e, appends to `window.__testAnalytics: Array<{ name, props }>` for assertion.

### Events emitted

| Event | Props | Fired when |
|---|---|---|
| `daily_opened` | `mode`, `dateAge` | Launcher mounts and a daily card renders |
| `daily_started` | `mode` | User clicks a daily Play CTA |
| `daily_attempted` | `mode`, `attemptIndex`, `scoreBucket` | Each individual attempt scored |
| `daily_completed` | `mode`, `bestScoreBucket`, `attemptsUsed` | 3rd attempt or user clicks Reveal |
| `daily_shared` | `mode`, `method` (share-api \| clipboard-text \| clipboard-link) | Share button activated |
| `free_started` | `mode` | Free-mode link clicked |
| `history_opened` | — | Calendar panel expanded |
| `history_cell_clicked` | `cellKind` (played \| unplayed-in-window \| rolled-off) | Calendar cell activated |
| `streak_reached_milestone` | `days` (3 \| 7 \| 14 \| 30 \| 100) | Celebration overlay fires |
| `launcher_dismissed` | `path` (link \| search \| escape \| card \| play-button) | Any launcher dismissal |
| `deep_link_opened` | `dateKind` (today \| past \| future \| invalid), `outcome` (played \| reveal \| redirect) | Hash parser resolves a daily URL |

Props deliberately bucketed (scoreBucket = quintile, dateAge = days-from-today integer) to avoid cardinality explosion and fingerprinting.

## Phasing, ship gates, risks, rollback

### Phases (5–7 weeks total; was 4–6 — revised up per critical review)

**Phase 1 — Foundation (week 1 + baseline wait).** Analytics wrapper + CF script. Baseline events on existing surfaces. Daily content pipeline: pools (curation blocks Phase 2 merge), picker, GHA, CI validator. `hashState.ts` parses `daily` but handler redirects to `/`. **No user-visible change.** Baseline analytics collects for ≥ 14 days during Phases 2–3 ramp-up.

### Rollback

Each phase is a revertable PR. Phases 2–5 add new `localStorage` keys; none mutate existing keys. Reverting any phase does not corrupt user data. CF Web Analytics removal requires one DNS revert + removing one script tag.

## Known limitations

- **Timezone lag up to 6 h.** Timezones east of UTC experience a window where today's local date has begun but the GHA cron has not yet emitted that date's entry. Worst case: Samoa (+13), ~6 h after local midnight, users see `unavailable` state. Mitigated by 4×/day cron cadence. Full per-timezone rollover deferred to v1.1.
- **Multi-tab same-day play.** Two tabs open simultaneously can both reach the daily's third attempt before localStorage synchronizes. Last-write wins; neither attempt-record is lost (both stored), but `score` reflects the later completing tab's best-of-3. Acceptable for a single-player game.
- **View-source spoiling within today.** A motivated user who inspects network traffic can see today's daily IDs. We accept this — the daily's purpose is social synchrony, not tamper-proof secrecy.
- **Edge cache staleness.** GitHub Pages does not support custom `Cache-Control` headers. Once Cloudflare is fronting the origin (required for Web Analytics anyway), a CF Page Rule sets `Cache-Control: public, max-age=300` on `/daily/index.json`. Without this rule, stale windows can persist for CF's default edge TTL.
- **`country-pool` / `city-pool` drift.** If a data update changes an id after the pool was curated, CI fails. Manual re-curation required. Acceptable trade for content-quality control.
